### 1. users 설명

users는 로그인·권한·소유권의 기준 테이블이다.
reports, posts는 반드시 users를 참조하며,
시스템에서 “사람”을 식별하는 유일한 기준이 된다.

| 컬럼            | 예시 값                                              | 설명                          |
| ------------- | ------------------------------------------------- | --------------------------- |
| id            | 1                                                 | 사용자 고유 PK                   |
| email         | [leeyj3382@gmail.com](mailto:leeyj3382@gmail.com) | 로그인 ID (중복 불가)              |
| password_hash | `$2a$10$...`                                      | BCrypt 해시 값 (원문 비밀번호 저장 금지) |
| nickname      | yujun                                             | 게시판/마이페이지 표시용 이름            |
| role          | USER                                              | 권한 (기본값 USER)               |
| created_at    | 2026-01-09T15:10:00                               | 가입 시각                       |
| updated_at    | 2026-01-09T15:10:00                               | 정보 수정 시각                    |

---

### 2. reports 설명

reports는 사용자가 특정 **주식 종목(ticker)**을 입력해 생성한
**리서치 리포트(GPT 결과)**를 저장하는 테이블이다.

input_json : 사용자 요청 원문

sources_json : 가격·뉴스 등 외부 데이터 출처

result_json : GPT가 생성한 리포트 결과 원문(JSON 포맷)

| 컬럼           | 예시 값                                                                           | 설명               |
| ------------ | ------------------------------------------------------------------------------ | ---------------- |
| id           | 101                                                                            | 리포트 PK           |
| user_id      | 1                                                                              | 작성자 (`users.id`) |
| ticker       | AAPL                                                                           | 종목 코드            |
| market       | US                                                                             | 시장 구분 (US / KR)  |
| summary      | 아이폰 수요 둔화 우려 vs 서비스 매출 성장                                               | 리스트용 한 줄 요약      |
| input_json   | `{"ticker":"AAPL","horizon":"1m","focus":"risk"}`                              | 사용자 요청 파라미터      |
| sources_json | `{"price":{"source":"...","asOf":"..."},"news":[{"title":"...","url":"..."}]}` | 데이터 출처 링크        |
| result_json  | `{"overview":...,"bull":...,"base":...,"bear":...}`                            | GPT 결과(JSON 포맷)  |
| created_at   | 2026-01-09T16:00:00                                                            | 리포트 생성 시각        |

---


### 3. posts 설명

posts는 자유 게시판 글을 저장하는 테이블이다.
댓글, 좋아요 등의 기능은 MVP 범위에서 제외하고
게시글 단위 CRUD만 먼저 구현한다.

| 컬럼         | 예시 값                    | 설명               |
| ---------- | ----------------------- | ---------------- |
| id         | 501                     | 게시글 PK           |
| user_id    | 1                       | 작성자 (`users.id`) |
| title      | AAPL 리포트 포맷 이렇게 하면 좋을 듯 | 게시글 제목           |
| content    | 최근 이슈 섹션에 출처 링크를 추가하면…  | 게시글 본문           |
| created_at | 2026-01-09T17:20:00     | 작성 시각            |
| updated_at | 2026-01-09T17:35:00     | 수정 시각            |

---


### 0. 관계 설명 (e0)

users.id는 시스템의 **“사람 기준”**이다.

reports, posts는 반드시 user_id로 users를 참조한다.

따라서 마이페이지 / 내 글 / 내 리포트 조회는 다음 조건으로 구현된다.

WHERE user_id = ?
